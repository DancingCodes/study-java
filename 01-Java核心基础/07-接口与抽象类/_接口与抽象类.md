# 接口与抽象类

## 一、抽象类（Abstract Class）

### 问题引入

上一课的 `Shape` 父类有一个 `area()` 方法，返回 0.0：

```java
public double area() {
    return 0.0;
}
```

这个方法没有实际意义——谁会用一个面积为 0 的形状？它存在的唯一目的是让子类重写。但万一某个子类**忘了重写**，程序不会报错，只会默默返回 0.0，很难发现 bug。

**抽象类**就是为了解决这个问题：**强制子类必须重写某些方法**。

### 语法

```java
// abstract 修饰类 → 抽象类
public abstract class Shape {
    private String name;

    public Shape(String name) {
        this.name = name;
    }

    public String getName() {
        return name;
    }

    // abstract 修饰方法 → 抽象方法（没有方法体，连大括号都不写）
    public abstract double area();
}
```

子类**必须**实现所有抽象方法，否则编译报错：

```java
public class Circle extends Shape {
    private double radius;

    public Circle(String name, double radius) {
        super(name);
        this.radius = radius;
    }

    @Override
    public double area() {  // 不实现就报错
        return Math.PI * radius * radius;
    }
}
```

### 抽象类的规则

| 规则 | 说明 |
|------|------|
| 抽象类**不能 new** | `new Shape()` 编译报错，必须用子类 |
| 抽象方法**没有方法体** | 只写声明，不写 `{}` |
| 有抽象方法的类**必须**声明为 abstract | 否则编译报错 |
| 抽象类**可以有**普通方法和属性 | 不是所有方法都必须抽象 |
| 子类必须实现所有抽象方法 | 除非子类自己也是抽象类 |

### 什么时候用抽象类？

当你有一组类，它们**共享部分代码**（属性、普通方法），但**某些方法每个子类的实现不同**，就用抽象类。

## 二、接口（Interface）

### 什么是接口？

接口是一份**纯粹的契约**：只定义「能做什么」，不管「怎么做」。

```java
public interface Flyable {
    void fly();  // 接口中的方法默认是 public abstract，可以不写
}

public interface Swimmable {
    void swim();
}
```

### 实现接口

用 `implements` 关键字，一个类可以实现**多个**接口：

```java
public class Duck extends Animal implements Flyable, Swimmable {
    @Override
    public void fly() {
        System.out.println("鸭子在飞");
    }

    @Override
    public void swim() {
        System.out.println("鸭子在游泳");
    }
}
```

```java
Duck duck = new Duck("唐老鸭", 2);
duck.fly();   // 鸭子在飞
duck.swim();  // 鸭子在游泳
```

### 接口的规则

| 规则 | 说明 |
|------|------|
| 接口不能 new | 和抽象类一样 |
| 方法默认是 `public abstract` | 可以省略不写 |
| 属性默认是 `public static final` | 也就是常量，如 `int MAX = 100;` |
| 一个类可以实现**多个**接口 | 弥补了 Java 单继承的限制 |
| 实现类必须实现接口的**所有**方法 | 否则编译报错 |

### 接口中的默认方法（Java 8+）

接口也可以有带方法体的方法，用 `default` 修饰：

```java
public interface Flyable {
    void fly();

    // 默认方法：有方法体，实现类可以不重写
    default void land() {
        System.out.println("降落");
    }
}
```

为什么需要？接口一旦发布，如果新增一个抽象方法，所有实现类都要改——用 `default` 就不用。

### 接口中的静态方法（Java 8+）

```java
public interface MathUtils {
    static int add(int a, int b) {
        return a + b;
    }
}

// 用接口名直接调用
MathUtils.add(1, 2);  // 3
```

## 三、抽象类 vs 接口

| 对比项 | 抽象类 | 接口 |
|--------|--------|------|
| 关键字 | `abstract class` | `interface` |
| 继承/实现 | `extends`（单继承） | `implements`（多实现） |
| 构造器 | **有** | **没有** |
| 属性 | 任意属性 | 只能是常量（`public static final`） |
| 方法 | 可以有普通方法和抽象方法 | 默认是抽象方法（Java 8+ 可以有 default 方法） |
| 设计思路 | **是什么**（is-a）：Dog is an Animal | **能做什么**（can-do）：Duck can Fly |

### 怎么选？

- 多个类有**共同的属性和方法实现** → 抽象类
- 多个**不相关的类**需要有**相同的能力** → 接口
- 不确定 → 优先用接口（更灵活）

实际例子：
```
Animal（抽象类）
├── Dog
├── Cat
└── Duck implements Flyable, Swimmable

Airplane implements Flyable   // 飞机不是动物，但也能飞
Fish implements Swimmable     // 鱼不是鸭子，但也能游
```

`Flyable` 只能是接口，不能是抽象类——因为 Duck 和 Airplane 没有共同的父类。

## 四、接口的多态

接口也可以作为类型使用，和父类多态一样：

```java
Flyable f1 = new Duck("唐老鸭", 2);
Flyable f2 = new Airplane();

f1.fly();  // 鸭子在飞
f2.fly();  // 飞机在飞
```

```java
public static void makeFly(Flyable flyable) {
    flyable.fly();  // 传什么就飞什么
}
```
