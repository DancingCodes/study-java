# 异常处理

## 一、什么是异常？

程序运行时出现的错误就是异常。比如：

```java
int[] arr = {1, 2, 3};
System.out.println(arr[5]);  // ArrayIndexOutOfBoundsException

String s = null;
s.length();  // NullPointerException

int result = 10 / 0;  // ArithmeticException
```

如果不处理，程序直接崩溃。异常处理就是让程序在出错时**不崩溃，能兜住**。

## 二、异常体系

```
Throwable（祖宗）
├── Error（严重错误，程序无法处理）
│   ├── OutOfMemoryError（内存溢出）
│   └── StackOverflowError（栈溢出）
└── Exception（异常，程序可以处理）
    ├── RuntimeException（运行时异常，编译不检查）
    │   ├── NullPointerException
    │   ├── ArrayIndexOutOfBoundsException
    │   ├── ArithmeticException
    │   ├── ClassCastException
    │   └── IllegalArgumentException
    └── 其他 Exception（编译时异常，必须处理）
        ├── IOException
        ├── SQLException
        └── FileNotFoundException
```

### 两类异常的区别

| | 运行时异常（RuntimeException） | 编译时异常（Checked Exception） |
|--|-------------------------------|-------------------------------|
| 编译器检查 | 不检查，编译能过 | 必须处理，否则编译报错 |
| 原因 | 通常是代码写错了（空指针、越界） | 外部因素（文件不存在、网络断开） |
| 处理方式 | 可以不 try/catch，修复代码即可 | 必须 try/catch 或 throws |

## 三、try / catch / finally

### 基本语法

```java
try {
    // 可能出异常的代码
    int result = 10 / 0;
} catch (ArithmeticException e) {
    // 出异常时执行
    System.out.println("除以零了：" + e.getMessage());
} finally {
    // 无论是否异常，都会执行
    System.out.println("finally 一定会执行");
}
```

### 执行流程

**没有异常时**：try → finally（跳过 catch）

**有异常时**：try（执行到出错的那一行就跳出）→ catch → finally

### 多个 catch

```java
try {
    String s = null;
    s.length();
} catch (NullPointerException e) {
    System.out.println("空指针：" + e.getMessage());
} catch (Exception e) {
    // 范围大的放后面（Exception 能兜住所有异常）
    System.out.println("其他异常：" + e.getMessage());
}
```

> **注意**：范围小的 catch 放前面，范围大的放后面。反过来编译报错。

### Java 7+ 多异常合并

```java
try {
    // ...
} catch (NullPointerException | ArithmeticException e) {
    System.out.println("出错了：" + e.getMessage());
}
```

### finally 的作用

无论是否异常都会执行，通常用来**释放资源**（关闭文件、关闭数据库连接）：

```java
FileReader reader = null;
try {
    reader = new FileReader("test.txt");
    // 读文件...
} catch (IOException e) {
    System.out.println("读文件失败");
} finally {
    if (reader != null) {
        reader.close();  // 确保文件被关闭
    }
}
```

### try-with-resources（Java 7+，推荐）

自动关闭资源，不用手写 finally：

```java
try (FileReader reader = new FileReader("test.txt")) {
    // 读文件...
} catch (IOException e) {
    System.out.println("读文件失败");
}
// reader 自动关闭，不用写 finally
```

> 资源类必须实现 `AutoCloseable` 接口（Java 的 IO 类都实现了）。

## 四、throw 和 throws

### throw — 手动抛出异常

```java
public static void setAge(int age) {
    if (age < 0) {
        throw new IllegalArgumentException("年龄不能为负数：" + age);
    }
    System.out.println("年龄设置为：" + age);
}

setAge(-1);  // 抛出 IllegalArgumentException: 年龄不能为负数：-1
```

`throw` 是在方法**内部**主动抛出一个异常对象。

### throws — 声明可能抛出的异常

```java
// 告诉调用者：这个方法可能抛出 IOException，你要处理
public static void readFile(String path) throws IOException {
    FileReader reader = new FileReader(path);
}
```

`throws` 写在方法签名上，意思是「我不处理，谁调用谁处理」。

### throw vs throws

| | throw | throws |
|--|-------|--------|
| 位置 | 方法体内 | 方法签名上 |
| 作用 | 抛出一个具体的异常对象 | 声明方法可能抛出的异常类型 |
| 后面跟 | 异常对象：`throw new XxxException()` | 异常类名：`throws IOException` |

## 五、自定义异常

实际开发中，系统自带的异常类往往不够用，需要自定义：

```java
// 继承 RuntimeException → 运行时异常（不用强制处理）
public class ScoreException extends RuntimeException {
    public ScoreException(String message) {
        super(message);  // 把错误信息传给父类
    }
}
```

使用：
```java
public static void setScore(double score) {
    if (score < 0 || score > 100) {
        throw new ScoreException("成绩不合法：" + score);
    }
    System.out.println("成绩：" + score);
}

try {
    setScore(150);
} catch (ScoreException e) {
    System.out.println(e.getMessage());  // 成绩不合法：150
}
```

### 自定义异常的选择

| 继承谁 | 特点 | 场景 |
|--------|------|------|
| `RuntimeException` | 运行时异常，调用者可以不处理 | 大部分业务异常（参数非法、状态错误） |
| `Exception` | 编译时异常，调用者必须处理 | 调用者必须知道并处理的异常 |

实际开发中**绝大多数自定义异常都继承 RuntimeException**。

## 六、异常链

捕获一个异常后，抛出新异常时，可以把原始异常带上：

```java
try {
    int result = 10 / 0;
} catch (ArithmeticException e) {
    throw new RuntimeException("计算失败", e);  // 第二个参数是原因（cause）
}
```

这样排查问题时可以追溯到最原始的异常原因。
