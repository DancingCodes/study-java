# 注解与反射

## 一、注解（Annotation）

### 什么是注解？

注解是一种**标记**，贴在类、方法、字段上，给编译器或框架提供额外信息。

> 比喻：注解就像快递箱上贴的标签 —— "易碎品"、"加急" —— 不改变箱子里的东西，但告诉快递员怎么处理。

你已经见过的注解：
- `@Override` — 告诉编译器这是重写的方法
- `@FunctionalInterface` — 标记函数式接口

### 内置注解

| 注解 | 作用 |
|------|------|
| `@Override` | 检查是否正确重写了父类方法 |
| `@Deprecated` | 标记已过时，不建议使用 |
| `@SuppressWarnings` | 抑制编译器警告 |

```java
public class Animal {
    @Deprecated
    public void sleep() {
        System.out.println("过时的方法");
    }
}
```

### 自定义注解

```java
import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;

// @Target：注解能贴在哪里
// @Retention：注解保留到什么阶段
@Target(ElementType.METHOD)        // 只能贴在方法上
@Retention(RetentionPolicy.RUNTIME) // 运行时保留（反射能读到）
public @interface MyTest {
    String value() default ""; // 注解的属性，有默认值
}
```

**@Target 常用值：**

| 值 | 能贴在哪 |
|----|----------|
| `ElementType.TYPE` | 类、接口 |
| `ElementType.METHOD` | 方法 |
| `ElementType.FIELD` | 字段 |

**@Retention 常用值：**

| 值 | 保留到 | 说明 |
|----|--------|------|
| `RetentionPolicy.SOURCE` | 源码 | 编译后丢弃（如 @Override） |
| `RetentionPolicy.CLASS` | class 文件 | 运行时读不到 |
| `RetentionPolicy.RUNTIME` | 运行时 | 反射能读到（最常用） |

使用自定义注解：

```java
public class UserService {
    @MyTest("测试获取用户")
    public void getUser() {
        System.out.println("获取用户");
    }

    @MyTest
    public void deleteUser() {
        System.out.println("删除用户");
    }

    public void updateUser() {
        System.out.println("更新用户");
    }
}
```

注解贴上去了，但还没有任何效果 —— 需要用**反射**来读取和处理。

## 二、反射（Reflection）

### 什么是反射？

反射是在**运行时**获取类的信息（类名、方法、字段、注解等），并可以动态调用方法、创建对象。

> 正常写代码：编译时就确定调用什么方法。
> 反射：运行时才决定调用什么方法。

### 获取 Class 对象

反射的起点是获取 `Class` 对象，三种方式：

```java
// 方式一：类名.class
Class<?> c1 = String.class;

// 方式二：对象.getClass()
String s = "hello";
Class<?> c2 = s.getClass();

// 方式三：Class.forName("全类名")
Class<?> c3 = Class.forName("java.lang.String");
```

### 获取类的信息

```java
Class<?> clazz = UserService.class;

// 获取类名
System.out.println(clazz.getName());       // 包名.UserService
System.out.println(clazz.getSimpleName()); // UserService

// 获取所有 public 方法（包括继承的）
Method[] methods = clazz.getMethods();

// 获取本类声明的所有方法（包括 private，不含继承的）
Method[] declaredMethods = clazz.getDeclaredMethods();

// 获取所有字段
Field[] fields = clazz.getDeclaredFields();
```

### 反射创建对象

```java
Class<?> clazz = UserService.class;

// 调用无参构造器创建对象
Object obj = clazz.getDeclaredConstructor().newInstance();
```

### 反射调用方法

```java
Class<?> clazz = UserService.class;
Object obj = clazz.getDeclaredConstructor().newInstance();

// 获取指定方法
Method method = clazz.getMethod("getUser");

// 调用方法
method.invoke(obj); // 相当于 obj.getUser()
```

### 反射读取注解

```java
Class<?> clazz = UserService.class;

for (Method method : clazz.getDeclaredMethods()) {
    // 判断方法上有没有 @MyTest 注解
    if (method.isAnnotationPresent(MyTest.class)) {
        // 获取注解对象
        MyTest annotation = method.getAnnotation(MyTest.class);
        System.out.println(method.getName() + " 上有 @MyTest，value = " + annotation.value());
    }
}
```

## 三、实战：手写简易测试框架

把注解和反射结合起来，实现一个迷你版的 JUnit：
- 贴了 `@MyTest` 的方法自动执行
- 没贴的不执行

```java
import java.lang.reflect.Method;

public class TestRunner {
    public static void run(Class<?> clazz) throws Exception {
        Object obj = clazz.getDeclaredConstructor().newInstance();

        for (Method method : clazz.getDeclaredMethods()) {
            if (method.isAnnotationPresent(MyTest.class)) {
                System.out.println("运行测试：" + method.getName());
                method.invoke(obj);
                System.out.println("--- 通过 ---");
            }
        }
    }

    public static void main(String[] args) throws Exception {
        run(UserService.class);
    }
}
```

运行结果：
```
运行测试：getUser
获取用户
--- 通过 ---
运行测试：deleteUser
删除用户
--- 通过 ---
```

`updateUser()` 没有 `@MyTest` 注解，所以不会被执行。

## 四、反射的应用场景

| 场景 | 说明 |
|------|------|
| 框架底层 | Spring 用反射创建 Bean、注入依赖 |
| 注解处理 | 读取注解执行对应逻辑 |
| 配置驱动 | 根据配置文件的类名动态创建对象 |
| 测试框架 | JUnit 用反射找到并执行测试方法 |

> 现阶段不需要深入反射的每个细节，理解原理和基本用法就够了。后面学 Spring 时会大量接触。
