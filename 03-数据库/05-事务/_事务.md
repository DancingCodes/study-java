# 事务

## 一、什么是事务

事务就是**一组操作要么全部成功，要么全部失败**，不能只成功一半。

经典例子——转账：
```
张三给李四转 500 元：
1. 张三余额 -500
2. 李四余额 +500
```

如果第 1 步成功了，第 2 步失败了（比如数据库崩了），张三少了 500 但李四没收到，钱就凭空消失了。事务保证这两步**要么都成功，要么都回滚**。

## 二、ACID 四大特性

| 特性 | 全称 | 含义 | 通俗理解 |
|------|------|------|----------|
| **A** | Atomicity（原子性） | 事务中的操作要么全做，要么全不做 | 转账要么都成功，要么都撤销 |
| **C** | Consistency（一致性） | 事务前后数据总是合法的 | 转账前后总金额不变 |
| **I** | Isolation（隔离性） | 多个事务并发执行时互不干扰 | 两个人同时转账不会乱 |
| **D** | Durability（持久性） | 事务提交后数据永久保存 | 提交了就不会丢 |

## 三、事务操作

```sql
-- 开启事务
START TRANSACTION;

-- 执行操作
UPDATE account SET balance = balance - 500 WHERE name = '张三';
UPDATE account SET balance = balance + 500 WHERE name = '李四';

-- 全部成功 → 提交
COMMIT;

-- 如果出错 → 回滚（撤销所有操作）
ROLLBACK;
```

三个关键词：
- `START TRANSACTION` — 开始事务
- `COMMIT` — 提交，所有操作生效
- `ROLLBACK` — 回滚，所有操作撤销

**注意**：MySQL 默认是自动提交的（每条 SQL 执行完自动 COMMIT）。开启事务后，必须手动 COMMIT 或 ROLLBACK。

```sql
-- 查看自动提交状态
SHOW VARIABLES LIKE 'autocommit';

-- 关闭自动提交（当前会话）
SET autocommit = 0;
```

## 四、并发问题

多个事务同时操作同一份数据时，可能出现以下问题：

### 4.1 脏读（Dirty Read）

事务 A 读到了事务 B **还没提交**的数据。如果 B 回滚了，A 读到的就是无效数据。

```
时间线：
事务 B：UPDATE salary = 50000 WHERE name = '张三'  （还没 COMMIT）
事务 A：SELECT salary FROM employee WHERE name = '张三'  → 读到 50000
事务 B：ROLLBACK  → 薪资恢复原值

结果：A 读到的 50000 是脏数据
```

### 4.2 不可重复读（Non-Repeatable Read）

事务 A 两次读同一行数据，中间事务 B **修改并提交**了，导致 A 前后读到的值不一样。

```
事务 A：SELECT salary → 15000
事务 B：UPDATE salary = 20000; COMMIT;
事务 A：SELECT salary → 20000（和第一次不一样了！）
```

### 4.3 幻读（Phantom Read）

事务 A 两次查询同一个范围，中间事务 B **插入**了新数据并提交，导致 A 前后查到的行数不一样。

```
事务 A：SELECT COUNT(*) WHERE department = '技术部' → 5 人
事务 B：INSERT INTO employee (name, department) VALUES ('新人', '技术部'); COMMIT;
事务 A：SELECT COUNT(*) WHERE department = '技术部' → 6 人（多了一行！）
```

**区别**：
- 脏读 — 读到别人**没提交**的
- 不可重复读 — 别人**改了**已有数据
- 幻读 — 别人**新增/删除**了数据

## 五、隔离级别

MySQL 提供 4 种隔离级别，级别越高越安全，但性能越低：

| 隔离级别 | 脏读 | 不可重复读 | 幻读 | 说明 |
|---------|------|-----------|------|------|
| READ UNCOMMITTED | ✅会 | ✅会 | ✅会 | 最低，啥问题都有 |
| READ COMMITTED | ❌不会 | ✅会 | ✅会 | 只读已提交的数据（Oracle 默认） |
| **REPEATABLE READ** | ❌不会 | ❌不会 | ✅可能 | **MySQL 默认**，同一事务内多次读结果一致 |
| SERIALIZABLE | ❌不会 | ❌不会 | ❌不会 | 最高，串行执行，性能最差 |

MySQL 默认是 **REPEATABLE READ**，实际开发中大多数情况够用了。

```sql
-- 查看当前隔离级别
SELECT @@transaction_isolation;

-- 设置隔离级别（当前会话）
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
```

## 六、实际开发中的事务

在后面学 Spring 时，事务用注解就能搞定：

```java
@Transactional
public void transfer(String from, String to, double amount) {
    accountMapper.deduct(from, amount);   // 扣款
    accountMapper.add(to, amount);        // 加款
    // 方法正常结束 → 自动 COMMIT
    // 抛异常 → 自动 ROLLBACK
}
```
