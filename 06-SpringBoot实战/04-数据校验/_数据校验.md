# 数据校验

## 一、为什么需要数据校验

上一节的创建商品接口，前端可以随便传数据：

```json
POST /products
{"name": "", "price": -100, "stock": -5}
```

名称为空、价格为负、库存为负 —— 这些数据如果直接存进数据库，后果不堪设想。

所以后端必须做数据校验：**永远不要信任前端传来的数据。**

手动写 if 校验：
```java
@PostMapping
public Result<Product> create(@RequestBody Product product) {
    if (product.getName() == null || product.getName().isEmpty()) {
        return Result.error(400, "商品名称不能为空");
    }
    if (product.getPrice() == null || product.getPrice().compareTo(BigDecimal.ZERO) <= 0) {
        return Result.error(400, "价格必须大于0");
    }
    // 还有 stock... 每个字段都要写 if
}
```

字段一多，满屏都是 if。Spring Boot 提供了注解式校验，一个注解搞定一个校验规则。

## 二、引入依赖

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>
```

## 三、常用校验注解

在实体类的字段上加注解，就能自动校验：

| 注解 | 作用 | 示例 |
|------|------|------|
| `@NotNull` | 不能为 null | `@NotNull(message = "ID不能为空")` |
| `@NotBlank` | 不能为 null 且不能为空字符串（只用于 String） | `@NotBlank(message = "名称不能为空")` |
| `@NotEmpty` | 不能为 null 且不能为空（用于集合、数组） | `@NotEmpty(message = "列表不能为空")` |
| `@Size` | 字符串/集合的长度范围 | `@Size(min = 2, max = 50)` |
| `@Min` | 最小值 | `@Min(value = 0, message = "库存不能为负")` |
| `@Max` | 最大值 | `@Max(value = 999999)` |
| `@DecimalMin` | 最小值（用于 BigDecimal） | `@DecimalMin(value = "0.01")` |
| `@Email` | 邮箱格式 | `@Email(message = "邮箱格式不正确")` |
| `@Pattern` | 正则匹配 | `@Pattern(regexp = "^1[3-9]\\d{9}$")` |

### 3.1 @NotNull vs @NotBlank vs @NotEmpty

这三个很容易搞混：

| 注解 | null | "" | " " | 适用类型 |
|------|------|-----|------|----------|
| `@NotNull` | 不通过 | 通过 | 通过 | 所有类型 |
| `@NotBlank` | 不通过 | 不通过 | 不通过 | 仅 String |
| `@NotEmpty` | 不通过 | 不通过 | 通过 | String、集合、数组 |

简单记：
- 数字类型（Integer、Long、BigDecimal）→ 用 `@NotNull`
- 字符串 → 用 `@NotBlank`（最严格，连空格都不放过）
- 集合 → 用 `@NotEmpty`

## 四、在实体类上加校验

```java
@Data
@TableName("product")
public class Product {

    @TableId(type = IdType.AUTO)
    private Long id;

    @NotBlank(message = "商品名称不能为空")
    @Size(min = 2, max = 50, message = "商品名称长度必须在2-50之间")
    private String name;

    @NotNull(message = "价格不能为空")
    @DecimalMin(value = "0.01", message = "价格必须大于0")
    private BigDecimal price;

    @NotNull(message = "库存不能为空")
    @Min(value = 0, message = "库存不能为负数")
    private Integer stock;

    private LocalDateTime createTime;
    private LocalDateTime updateTime;

    @TableLogic
    private Integer deleted;
}
```

## 五、在 Controller 中触发校验

光在实体类上加注解还不够，还要在 Controller 方法参数上加 `@Valid` 或 `@Validated`：

```java
import jakarta.validation.Valid;

@PostMapping
public Result<Product> create(@Valid @RequestBody Product product) {
    //                         ↑ 加上 @Valid，校验才会生效
    productService.save(product);
    return Result.success(product);
}

@PutMapping("/{id}")
public Result<Product> update(@PathVariable Long id, @Valid @RequestBody Product product) {
    product.setId(id);
    productService.updateById(product);
    return Result.success(product);
}
```

如果校验不通过，Spring Boot 会抛出 `MethodArgumentNotValidException`，默认返回 400 错误。但默认的错误格式不友好，需要全局异常处理来统一格式（下一节学）。

## 六、分组校验

### 6.1 问题场景

同一个 `Product` 类，创建和更新时校验规则不同：
- **创建**时：id 不需要传（数据库自增），name、price、stock 必填
- **更新**时：id 必须传，name、price、stock 可选（只更新传了的字段）

如果不分组，创建时 id 被 `@NotNull` 拦住了，或者更新时所有字段都必传，都不合理。

### 6.2 定义分组接口

```java
public interface CreateGroup {
}

public interface UpdateGroup {
}
```

就是空接口，纯粹当标记用。

### 6.3 实体类指定分组

```java
@Data
@TableName("product")
public class Product {

    @NotNull(message = "ID不能为空", groups = UpdateGroup.class)  // 只在更新时校验
    @TableId(type = IdType.AUTO)
    private Long id;

    @NotBlank(message = "商品名称不能为空", groups = CreateGroup.class)  // 只在创建时必填
    @Size(min = 2, max = 50, message = "商品名称长度必须在2-50之间",
          groups = {CreateGroup.class, UpdateGroup.class})  // 创建和更新都校验长度
    private String name;

    @NotNull(message = "价格不能为空", groups = CreateGroup.class)
    @DecimalMin(value = "0.01", message = "价格必须大于0",
               groups = {CreateGroup.class, UpdateGroup.class})
    private BigDecimal price;

    @NotNull(message = "库存不能为空", groups = CreateGroup.class)
    @Min(value = 0, message = "库存不能为负数",
         groups = {CreateGroup.class, UpdateGroup.class})
    private Integer stock;

    private LocalDateTime createTime;
    private LocalDateTime updateTime;

    @TableLogic
    private Integer deleted;
}
```

### 6.4 Controller 指定分组

用 `@Validated` 替代 `@Valid`（`@Validated` 支持分组，`@Valid` 不支持）：

```java
import org.springframework.validation.annotation.Validated;

@PostMapping
public Result<Product> create(@Validated(CreateGroup.class) @RequestBody Product product) {
    //                         ↑ 创建时用 CreateGroup
    productService.save(product);
    return Result.success(product);
}

@PutMapping("/{id}")
public Result<Product> update(@PathVariable Long id,
                              @Validated(UpdateGroup.class) @RequestBody Product product) {
    //                         ↑ 更新时用 UpdateGroup
    product.setId(id);
    productService.updateById(product);
    return Result.success(product);
}
```

## 七、自定义校验注解（了解）

内置注解不够用时，可以自定义。比如校验商品名称不能包含敏感词：

```java
// 1. 定义注解
@Target({ElementType.FIELD})
@Retention(RetentionPolicy.RUNTIME)
@Constraint(validatedBy = NoSensitiveWordValidator.class)
public @interface NoSensitiveWord {
    String message() default "包含敏感词";
    Class<?>[] groups() default {};
    Class<? extends Payload>[] payload() default {};
}

// 2. 实现校验器
public class NoSensitiveWordValidator implements ConstraintValidator<NoSensitiveWord, String> {
    private static final List<String> SENSITIVE_WORDS = List.of("违禁", "假冒");

    @Override
    public boolean isValid(String value, ConstraintValidatorContext context) {
        if (value == null) return true;  // null 交给 @NotBlank 处理
        return SENSITIVE_WORDS.stream().noneMatch(value::contains);
    }
}

// 3. 使用
@NoSensitiveWord
private String name;
```

了解即可，实际项目中用内置注解就能覆盖 90% 的场景。

## 八、@Valid vs @Validated 对比

| | @Valid | @Validated |
|---|--------|------------|
| 来源 | Jakarta EE 标准 | Spring 扩展 |
| 分组校验 | 不支持 | 支持 |
| 用在哪 | 方法参数、字段 | 方法参数、类 |
| 推荐 | 不需要分组时用 | 需要分组时用 |

简单记：不分组用 `@Valid`，要分组用 `@Validated`。

## 练习

### 练习 1：给商品实体加校验

在上一节的 `mybatis-plus-demo` 项目基础上：

1. `pom.xml` 添加 `spring-boot-starter-validation` 依赖
2. 在 `Product` 实体类的字段上添加校验注解：
   - name：不能为空，长度 2-50
   - price：不能为空，必须大于 0
   - stock：不能为空，不能为负数
3. 在 Controller 的 create 和 update 方法参数上加 `@Valid`
4. 用 `test-api.http` 测试：发一个空 name 的请求，看是否返回 400 错误

### 练习 2：分组校验

1. 创建 `validation/CreateGroup.java` 和 `validation/UpdateGroup.java` 两个空接口
2. 给 `Product` 的校验注解加上分组（创建时 name/price/stock 必填，更新时 id 必填其他可选）
3. Controller 中把 `@Valid` 改成 `@Validated(CreateGroup.class)` 和 `@Validated(UpdateGroup.class)`
4. 测试：创建时不传 name 应该报错，更新时不传 name 应该通过
