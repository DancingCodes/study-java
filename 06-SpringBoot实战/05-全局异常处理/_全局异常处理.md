# 全局异常处理

## 一、为什么需要全局异常处理

上一节加了数据校验后，校验不通过时 Spring Boot 默认返回这样的错误：

```json
{
    "timestamp": "2024-03-15T10:30:00.000+00:00",
    "status": 400,
    "error": "Bad Request",
    "path": "/products"
}
```

问题：
- 格式和我们的 `Result` 不统一，前端要写两套解析逻辑
- 没有具体的错误信息（哪个字段不对？）
- 如果代码运行时抛异常（空指针、数据库异常等），默认返回 500 + 一大堆堆栈信息

我们需要一个统一的地方来「兜底」所有异常，把它们转成 `Result` 格式返回。

## 二、@RestControllerAdvice

Spring Boot 提供了 `@RestControllerAdvice` 注解，可以拦截所有 Controller 抛出的异常：

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    // 拦截某种异常
    @ExceptionHandler(异常类.class)
    public Result<?> handleXxx(异常类 e) {
        return Result.error(错误码, 错误信息);
    }
}
```

**原理**：
- `@RestControllerAdvice` = `@ControllerAdvice` + `@ResponseBody`
- `@ExceptionHandler` 指定要拦截哪种异常
- 方法返回 `Result`，自动转 JSON

类比：`@RestControllerAdvice` 就像一个全局的 try-catch，你不需要在每个 Controller 方法里写 try-catch 了。

## 三、处理常见异常

### 3.1 参数校验异常

当 `@Valid` 校验不通过时，会抛 `MethodArgumentNotValidException`：

```java
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.validation.FieldError;

@ExceptionHandler(MethodArgumentNotValidException.class)
public Result<?> handleValidation(MethodArgumentNotValidException e) {
    // 取出第一个校验错误信息
    FieldError fieldError = e.getBindingResult().getFieldError();
    String message = fieldError != null ? fieldError.getDefaultMessage() : "参数校验失败";
    return Result.error(400, message);
}
```

现在校验不通过返回：
```json
{"code": 400, "message": "商品名称不能为空", "data": null}
```

格式统一了，错误信息也清晰了。

### 3.2 请求参数缺失异常

`@RequestParam` 必传参数没传时，抛 `MissingServletRequestParameterException`：

```java
import org.springframework.web.bind.MissingServletRequestParameterException;

@ExceptionHandler(MissingServletRequestParameterException.class)
public Result<?> handleMissingParam(MissingServletRequestParameterException e) {
    return Result.error(400, "缺少必要参数：" + e.getParameterName());
}
```

### 3.3 路径参数类型错误

比如 `/products/abc`，id 期望 Long 但传了字符串，抛 `MethodArgumentTypeMismatchException`：

```java
import org.springframework.web.method.annotation.MethodArgumentTypeMismatchException;

@ExceptionHandler(MethodArgumentTypeMismatchException.class)
public Result<?> handleTypeMismatch(MethodArgumentTypeMismatchException e) {
    return Result.error(400, "参数类型错误：" + e.getName());
}
```

### 3.4 自定义业务异常

有些错误是业务逻辑层面的，比如「商品不存在」「库存不足」。这些需要自定义异常类：

```java
public class BusinessException extends RuntimeException {

    private final Integer code;

    public BusinessException(Integer code, String message) {
        super(message);
        this.code = code;
    }

    public Integer getCode() {
        return code;
    }
}
```

在 Service 层抛出：
```java
@Override
public Product getProductById(Long id) {
    Product product = this.getById(id);
    if (product == null) {
        throw new BusinessException(404, "商品不存在");
    }
    return product;
}
```

全局拦截：
```java
@ExceptionHandler(BusinessException.class)
public Result<?> handleBusiness(BusinessException e) {
    return Result.error(e.getCode(), e.getMessage());
}
```

### 3.5 兜底 — 未知异常

所有没有被上面拦截到的异常，用 `Exception.class` 兜底：

```java
@ExceptionHandler(Exception.class)
public Result<?> handleException(Exception e) {
    // 生产环境不要把详细错误信息返回给前端（可能暴露敏感信息）
    // 但要记录日志，方便排查
    e.printStackTrace();  // 后面学了日志系统会换成 log.error()
    return Result.error(500, "服务器内部错误");
}
```

## 四、完整的全局异常处理器

```java
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.MissingServletRequestParameterException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;
import org.springframework.web.method.annotation.MethodArgumentTypeMismatchException;
import org.springframework.validation.FieldError;

@RestControllerAdvice
public class GlobalExceptionHandler {

    // 参数校验异常（@Valid 不通过）
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<?> handleValidation(MethodArgumentNotValidException e) {
        FieldError fieldError = e.getBindingResult().getFieldError();
        String message = fieldError != null ? fieldError.getDefaultMessage() : "参数校验失败";
        return Result.error(400, message);
    }

    // 缺少必要参数
    @ExceptionHandler(MissingServletRequestParameterException.class)
    public Result<?> handleMissingParam(MissingServletRequestParameterException e) {
        return Result.error(400, "缺少必要参数：" + e.getParameterName());
    }

    // 参数类型错误
    @ExceptionHandler(MethodArgumentTypeMismatchException.class)
    public Result<?> handleTypeMismatch(MethodArgumentTypeMismatchException e) {
        return Result.error(400, "参数类型错误：" + e.getName());
    }

    // 自定义业务异常
    @ExceptionHandler(BusinessException.class)
    public Result<?> handleBusiness(BusinessException e) {
        return Result.error(e.getCode(), e.getMessage());
    }

    // 兜底 — 所有未处理的异常
    @ExceptionHandler(Exception.class)
    public Result<?> handleException(Exception e) {
        e.printStackTrace();
        return Result.error(500, "服务器内部错误");
    }
}
```

**注意方法顺序**：Spring 会自动匹配最精确的异常类型，所以 `Exception.class`（兜底）放最后就行，不影响上面的精确匹配。

## 五、业务异常体系设计

一个简单的 `BusinessException` 在小项目够用了。稍大一点的项目会用枚举管理错误码：

```java
public enum ErrorCode {
    PRODUCT_NOT_FOUND(1001, "商品不存在"),
    STOCK_NOT_ENOUGH(1002, "库存不足"),
    USER_NOT_FOUND(2001, "用户不存在"),
    UNAUTHORIZED(3001, "未登录");

    private final Integer code;
    private final String message;

    ErrorCode(Integer code, String message) {
        this.code = code;
        this.message = message;
    }

    public Integer getCode() { return code; }
    public String getMessage() { return message; }
}
```

```java
public class BusinessException extends RuntimeException {

    private final Integer code;

    public BusinessException(ErrorCode errorCode) {
        super(errorCode.getMessage());
        this.code = errorCode.getCode();
    }

    public BusinessException(Integer code, String message) {
        super(message);
        this.code = code;
    }

    public Integer getCode() {
        return code;
    }
}
```

使用：
```java
throw new BusinessException(ErrorCode.PRODUCT_NOT_FOUND);
throw new BusinessException(ErrorCode.STOCK_NOT_ENOUGH);
```

好处：错误码集中管理，不会出现同一个错误在不同地方用不同 code 的问题。

## 六、异常处理流程总结

```
前端请求 → Controller
             ↓
         正常执行 → 返回 Result.success()
             ↓
         抛异常 → GlobalExceptionHandler 拦截
             ↓
         匹配 @ExceptionHandler
             ↓
         返回 Result.error()
```

前端只需要判断 `code` 是否为 200：
```javascript
if (res.data.code === 200) {
    // 成功
} else {
    alert(res.data.message);  // 显示错误信息
}
```

## 练习

### 练习 1：实现全局异常处理器

1. 创建 `exception/BusinessException.java` — 自定义业务异常（字段：code、message）
2. 创建 `exception/GlobalExceptionHandler.java` — 全局异常处理，拦截以下异常：
   - `MethodArgumentNotValidException` — 校验不通过，返回 400
   - `MissingServletRequestParameterException` — 缺少参数，返回 400
   - `MethodArgumentTypeMismatchException` — 类型错误，返回 400
   - `BusinessException` — 业务异常，返回自定义 code
   - `Exception` — 兜底，返回 500

### 练习 2：在 Service 层使用业务异常

1. 在 `ProductService` 接口中新增方法 `getProductById(Long id)`
2. 在 `ProductServiceImpl` 中实现：查询为 null 时抛 `BusinessException(404, "商品不存在")`
3. Controller 的 `getById` 方法改为调用 `productService.getProductById(id)`
4. 测试：访问 `GET /products/999`（不存在的 ID），应返回 `{"code": 404, "message": "商品不存在", "data": null}`

### 练习 3：思考题

1. 如果不做全局异常处理，前端会收到什么样的错误响应？
2. 为什么 `BusinessException` 继承 `RuntimeException` 而不是 `Exception`？
3. 兜底的 `Exception` 处理器为什么不应该把 `e.getMessage()` 直接返回给前端？
