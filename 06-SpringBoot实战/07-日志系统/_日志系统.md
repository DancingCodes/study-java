# 日志系统

## 一、为什么需要日志

你之前调试代码可能用的是 `System.out.println()`，但它有很多问题：

| System.out.println | 日志框架 |
|---|---|
| 输出到控制台就没了 | 可以写入文件，永久保存 |
| 没有时间戳 | 自动记录时间、类名、线程 |
| 不能分级别 | 有 DEBUG/INFO/WARN/ERROR 级别 |
| 不能按条件开关 | 生产环境关 DEBUG，只留 WARN/ERROR |
| 性能差 | 异步写入，性能好 |

一句话：**生产环境绝对不能用 System.out.println，必须用日志框架。**

## 二、SLF4J + Logback

### 2.1 SLF4J 是什么

SLF4J（Simple Logging Facade for Java）是一个**日志门面**（接口），不是具体实现。

类比：SLF4J 就像 JDBC 接口，Logback/Log4j2 就像 MySQL 驱动 / PostgreSQL 驱动。你写代码面向接口，底层实现可以随时换。

### 2.2 Logback 是什么

Logback 是 SLF4J 的**默认实现**，Spring Boot 内置了它，不需要额外引依赖。

```
你的代码 → SLF4J（接口） → Logback（实现） → 控制台 / 文件
```

## 三、日志级别

从低到高，共 5 个级别：

| 级别 | 用途 | 示例 |
|------|------|------|
| `TRACE` | 最细粒度，追踪流程 | 方法入参出参（很少用） |
| `DEBUG` | 调试信息 | SQL 语句、变量值 |
| `INFO` | 重要业务信息 | 用户登录、订单创建、服务启动 |
| `WARN` | 警告，不影响运行但需关注 | 配置缺失用了默认值、重试 |
| `ERROR` | 错误，需要处理 | 数据库连接失败、空指针异常 |

**设置日志级别后，只输出该级别及以上的日志。** 比如设为 `INFO`，则 `TRACE` 和 `DEBUG` 不输出。

```
TRACE < DEBUG < INFO < WARN < ERROR
```

开发环境通常设为 `DEBUG`，生产环境设为 `INFO` 或 `WARN`。

## 四、使用日志

### 4.1 @Slf4j 注解（推荐）

Lombok 提供了 `@Slf4j` 注解，自动生成一个 `log` 对象：

```java
import lombok.extern.slf4j.Slf4j;

@Slf4j
@RestController
public class HelloController {

    @GetMapping("/hello")
    public String hello() {
        log.info("收到 hello 请求");
        return "Hello!";
    }
}
```

`@Slf4j` 等价于手写：
```java
private static final Logger log = LoggerFactory.getLogger(HelloController.class);
```

### 4.2 日志方法

```java
log.trace("trace 级别日志");
log.debug("debug 级别日志");
log.info("info 级别日志");
log.warn("warn 级别日志");
log.error("error 级别日志");
```

### 4.3 占位符 — 推荐写法

```java
// 用 {} 占位符，不要用字符串拼接
log.info("查询商品，ID：{}", id);
log.info("用户 {} 购买了 {} 件商品", username, count);

// 记录异常时，把异常对象放最后一个参数
try {
    // ...
} catch (Exception e) {
    log.error("处理订单失败，订单号：{}", orderId, e);  // e 会打印完整堆栈
}
```

**为什么用 `{}` 而不用字符串拼接？**

```java
// 差 — 即使日志级别不输出 debug，字符串拼接也会执行，浪费性能
log.debug("查询结果：" + result.toString());

// 好 — 如果 debug 级别不输出，{} 不会做拼接，零开销
log.debug("查询结果：{}", result);
```

## 五、application.yml 配置日志级别

最简单的方式，在 yml 中配置：

```yaml
logging:
  level:
    root: info                          # 全局默认 INFO
    com.study.logdemo: debug            # 自己的包设为 DEBUG
    com.baomidou.mybatisplus: warn      # 第三方包设为 WARN
```

## 六、logback-spring.xml 配置

yml 只能做简单配置。需要更细致的控制（输出到文件、按日期滚动、限制大小），要用 `logback-spring.xml`：

在 `src/main/resources/` 下创建 `logback-spring.xml`：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration>

    <!-- 控制台输出 -->
    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>

    <!-- 文件输出 — 按日期滚动 -->
    <appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>logs/app.log</file>
        <rollingPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedRollingPolicy">
            <fileNamePattern>logs/app.%d{yyyy-MM-dd}.%i.log</fileNamePattern>
            <maxFileSize>10MB</maxFileSize>       <!-- 单个文件最大 10MB -->
            <maxHistory>30</maxHistory>            <!-- 保留 30 天 -->
            <totalSizeCap>1GB</totalSizeCap>      <!-- 总大小上限 1GB -->
        </rollingPolicy>
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>

    <!-- 开发环境 -->
    <springProfile name="dev">
        <root level="INFO">
            <appender-ref ref="CONSOLE" />
        </root>
        <logger name="com.study.logdemo" level="DEBUG" />
    </springProfile>

    <!-- 生产环境 -->
    <springProfile name="prod">
        <root level="WARN">
            <appender-ref ref="CONSOLE" />
            <appender-ref ref="FILE" />
        </root>
        <logger name="com.study.logdemo" level="INFO" />
    </springProfile>

</configuration>
```

**日志格式解读**：
```
%d{yyyy-MM-dd HH:mm:ss.SSS}  → 时间
[%thread]                      → 线程名
%-5level                       → 日志级别（左对齐，占 5 字符）
%logger{36}                    → 类名（最长 36 字符）
%msg                           → 日志内容
%n                             → 换行
```

输出效果：
```
2024-03-15 10:30:00.123 [http-nio-8080-exec-1] INFO  c.s.logdemo.controller.ProductController - 查询商品，ID：1
```

## 七、生产环境日志建议

1. **级别设为 INFO 或 WARN**，不要开 DEBUG（日志量太大）
2. **必须输出到文件**，不能只输出到控制台（容器重启控制台日志就没了）
3. **按日期 + 大小滚动**，避免单个日志文件几十 GB
4. **设置保留天数和总大小上限**，磁盘不会被日志撑满
5. **敏感信息不要打日志**（密码、手机号、身份证号等）
6. **异常必须打 ERROR 日志**，并带上完整堆栈（把异常对象放最后一个参数）

## 练习

### 练习 1：在 Controller 和 Service 中使用日志

1. 在 Controller 的每个方法入口记录 `log.info`（请求参数）
2. 在 Service 层记录业务关键步骤的 `log.debug`
3. 在全局异常处理器中用 `log.error` 替代 `e.printStackTrace()`
4. 启动项目，调用接口后观察控制台日志输出

**答案**：已在 `log-demo` 项目中实现。`ProductController` 使用 `@Slf4j` 注解，每个方法入口用 `log.info` 记录请求参数，`ProductServiceImpl` 用 `log.debug` 记录业务步骤，`GlobalExceptionHandler` 用 `log.error` 记录异常堆栈。

### 练习 2：配置 logback-spring.xml

1. 创建 `logback-spring.xml`，配置控制台 + 文件双输出
2. 开发环境输出 DEBUG，生产环境只输出 INFO 以上
3. 文件按日期滚动，单文件最大 10MB，保留 30 天
4. 启动项目后检查 `logs/` 目录下是否生成了日志文件

**答案**：已在 `log-demo/src/main/resources/logback-spring.xml` 中配置。使用 `<springProfile>` 区分 dev 和 prod 环境，dev 只输出到控制台（DEBUG 级别），prod 同时输出到控制台和文件（INFO 级别），文件用 `SizeAndTimeBasedRollingPolicy` 按日期+大小滚动。

### 练习 3：思考题

1. 为什么不能用 `System.out.println` 替代日志框架？
2. `log.debug("结果：" + obj)` 和 `log.debug("结果：{}", obj)` 有什么区别？
3. 生产环境日志级别为什么不能开 DEBUG？

**答案**：

1. `System.out.println` 没有级别控制、没有时间戳、不能写入文件、不能按环境开关、性能差。生产环境只输出到控制台，容器重启日志就丢失了。

2. 字符串拼接（`"结果：" + obj`）无论日志级别是否输出都会执行拼接和 `toString()` 操作，浪费性能。`{}` 占位符在日志级别不输出时不做任何拼接，零开销。

3. DEBUG 日志量巨大（比如每条 SQL 都会打印），会导致：磁盘被日志撑满、写日志影响应用性能、可能泄露敏感信息（SQL 参数中的手机号、密码等）。
