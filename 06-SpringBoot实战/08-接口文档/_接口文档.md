# 接口文档

## 一、为什么需要接口文档

后端写好了接口，前端怎么知道：
- 有哪些接口？URL 是什么？
- 每个接口用什么 HTTP 方法（GET/POST/PUT/DELETE）？
- 请求参数有哪些？哪些必传？什么类型？
- 返回数据长什么样？

传统做法是手写 Word 或 Markdown 文档，但问题很大：
- 代码改了，文档忘了改 → 文档和实际接口对不上
- 写文档耗时间，程序员不爱写
- 前端看了文档还是得手动构造请求测试

Swagger / OpenAPI 的解决方案：**从代码自动生成接口文档，还能在线测试。**

## 二、Swagger 与 OpenAPI

- **OpenAPI**：一套描述 REST API 的标准规范（JSON/YAML 格式）
- **Swagger**：围绕 OpenAPI 的一套工具集，最核心的是 **Swagger UI**（可视化页面）

简单理解：OpenAPI 是标准，Swagger 是实现这个标准的工具。

在 Spring Boot 3 中，我们使用 **springdoc-openapi** 库（不是旧版的 springfox，springfox 已经不维护了）。

## 三、项目搭建

### 3.1 添加依赖

```xml
<!-- springdoc-openapi：自动生成接口文档 + Swagger UI -->
<dependency>
    <groupId>org.springdoc</groupId>
    <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
    <version>2.3.0</version>
</dependency>
```

只需要这一个依赖，就同时获得了：
- OpenAPI 规范文件自动生成
- Swagger UI 页面

### 3.2 启动访问

启动项目后，浏览器访问：
- **Swagger UI 页面**：`http://localhost:8080/swagger-ui.html`
- **OpenAPI JSON**：`http://localhost:8080/v3/api-docs`

打开 Swagger UI 就能看到所有接口列表，还能直接在页面上填参数、发请求、看响应。

### 3.3 yml 配置（可选）

```yaml
springdoc:
  swagger-ui:
    path: /swagger-ui.html    # Swagger UI 访问路径（默认就是这个）
  api-docs:
    path: /v3/api-docs        # OpenAPI JSON 路径
```

默认配置就够用，一般不需要改。

## 四、常用注解

springdoc-openapi 会自动扫描 Controller 生成文档，但默认的文档信息不够友好。加上注解可以让文档更清晰。

### 4.1 @Tag — 给 Controller 分组

```java
@Tag(name = "商品管理", description = "商品的增删改查接口")
@RestController
@RequestMapping("/products")
public class ProductController {
    // ...
}
```

Swagger UI 上会按 Tag 分组显示，比默认的类名好看多了。

### 4.2 @Operation — 描述单个接口

```java
@Operation(summary = "根据ID查询商品", description = "传入商品ID，返回商品详情")
@GetMapping("/{id}")
public Result<Product> getById(@PathVariable Long id) {
    // ...
}
```

- `summary`：一句话描述（显示在列表中）
- `description`：详细说明（展开后显示）

### 4.3 @Parameter — 描述参数

```java
@Operation(summary = "搜索商品")
@GetMapping("/search")
public Result<List<Product>> search(
        @Parameter(description = "商品名称（模糊搜索）") @RequestParam(required = false) String name,
        @Parameter(description = "最低价格") @RequestParam(required = false) Double minPrice,
        @Parameter(description = "最高价格") @RequestParam(required = false) Double maxPrice
) {
    // ...
}
```

### 4.4 @Schema — 描述实体类字段

```java
@Data
public class Product {

    @Schema(description = "商品ID", example = "1")
    private Long id;

    @Schema(description = "商品名称", example = "iPhone 15")
    private String name;

    @Schema(description = "价格", example = "5999.00")
    private Double price;

    @Schema(description = "库存数量", example = "100")
    private Integer stock;
}
```

`@Schema` 让前端在文档页面能看到每个字段的含义和示例值。

### 4.5 注解汇总

| 注解 | 放在哪 | 作用 |
|------|--------|------|
| `@Tag` | Controller 类上 | 接口分组 |
| `@Operation` | 方法上 | 描述单个接口 |
| `@Parameter` | 方法参数上 | 描述请求参数 |
| `@Schema` | 实体类字段上 | 描述字段含义和示例 |

## 五、完整示例

```java
@Tag(name = "商品管理", description = "商品的增删改查接口")
@RestController
@RequestMapping("/products")
public class ProductController {

    @Operation(summary = "根据ID查询商品")
    @GetMapping("/{id}")
    public Result<Product> getById(
            @Parameter(description = "商品ID") @PathVariable Long id) {
        Product product = new Product(id, "iPhone 15", 5999.0, 100);
        return Result.success(product);
    }

    @Operation(summary = "查询全部商品")
    @GetMapping
    public Result<List<Product>> list() {
        // ...
    }

    @Operation(summary = "创建商品")
    @PostMapping
    public Result<Product> create(@RequestBody Product product) {
        // ...
    }

    @Operation(summary = "更新商品")
    @PutMapping("/{id}")
    public Result<Product> update(
            @Parameter(description = "商品ID") @PathVariable Long id,
            @RequestBody Product product) {
        // ...
    }

    @Operation(summary = "删除商品")
    @DeleteMapping("/{id}")
    public Result<Void> delete(
            @Parameter(description = "商品ID") @PathVariable Long id) {
        // ...
    }
}
```

启动后打开 `http://localhost:8080/swagger-ui.html`，你会看到：
- 商品管理分组
- 每个接口有中文描述
- 点开接口可以直接测试
- 请求体和响应体都有字段说明

## 六、Knife4j（了解）

Knife4j 是国人基于 Swagger 做的增强版 UI，界面更美观、功能更丰富（中文友好、支持离线文档导出等）。

```xml
<!-- 用 Knife4j 替代默认的 Swagger UI -->
<dependency>
    <groupId>com.github.xiaoymin</groupId>
    <artifactId>knife4j-openapi3-jakarta-spring-boot-starter</artifactId>
    <version>4.3.0</version>
</dependency>
```

引入后访问 `http://localhost:8080/doc.html` 就是 Knife4j 的界面。

注意：Knife4j 和 springdoc-openapi 二选一即可，Knife4j 内部已经包含了 springdoc，不要重复引入。

了解即可，我们的练习用 springdoc-openapi 就够了。

## 七、生产环境关闭文档

接口文档只在开发和测试环境使用，生产环境必须关闭（安全风险）：

```yaml
# application-prod.yml
springdoc:
  api-docs:
    enabled: false
  swagger-ui:
    enabled: false
```

## 练习

### 练习 1：给商品接口添加文档注解

1. 在 `swagger-demo` 项目中，给 `ProductController` 添加 `@Tag`、`@Operation`、`@Parameter` 注解
2. 给 `Product` 实体类添加 `@Schema` 注解
3. 启动项目，访问 `http://localhost:8080/swagger-ui.html` 查看效果
4. 在 Swagger UI 页面上直接测试接口

**答案**：已在 `swagger-demo` 项目中实现。`ProductController` 使用 `@Tag(name = "商品管理")` 分组，每个方法用 `@Operation(summary = "...")` 描述，参数用 `@Parameter(description = "...")` 说明。`Product` 实体类字段用 `@Schema(description = "...", example = "...")` 标注。

### 练习 2：思考题

1. 为什么不推荐手写接口文档？
2. springdoc-openapi 和 springfox 有什么区别？Spring Boot 3 应该用哪个？
3. 为什么生产环境要关闭 Swagger UI？

**答案**：

1. 手写文档容易和代码不同步，代码改了文档忘了改，导致前后端联调时发现接口对不上。自动生成的文档永远和代码一致，还能在线测试。

2. springfox 已经停止维护，不支持 Spring Boot 3 和 Jakarta 命名空间。springdoc-openapi 是活跃维护的，完全兼容 Spring Boot 3，应该用 springdoc-openapi。

3. Swagger UI 暴露了所有接口的路径、参数、返回值结构，相当于把 API 地图完整交给攻击者，是严重的安全风险。生产环境必须通过配置 `springdoc.api-docs.enabled=false` 关闭。
