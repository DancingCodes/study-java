# 文件上传下载

## 一、文件上传下载的使用场景

几乎所有项目都涉及文件操作：
- 用户上传头像
- 商品上传图片
- 导入 Excel 数据
- 下载报表、合同、发票

## 二、MultipartFile — 接收上传文件

Spring Boot 用 `MultipartFile` 接收前端上传的文件：

```java
@PostMapping("/upload")
public Result<String> upload(@RequestParam("file") MultipartFile file) {
    // file.getOriginalFilename() — 原始文件名
    // file.getSize() — 文件大小（字节）
    // file.getContentType() — 文件类型（image/png 等）
    // file.getInputStream() — 文件内容流
    // file.transferTo(dest) — 保存到目标文件
}
```

前端用 `multipart/form-data` 格式发送：
```html
<form action="/upload" method="post" enctype="multipart/form-data">
    <input type="file" name="file">
    <button type="submit">上传</button>
</form>
```

## 三、文件存储到本地

### 3.1 配置上传路径

在 `application.yml` 中配置：
```yaml
app:
  upload-dir: ./uploads   # 上传文件存储目录
```

### 3.2 文件名处理 — UUID 防重名

如果两个用户都上传了 `photo.jpg`，后面的会覆盖前面的。解决方案：用 UUID 生成唯一文件名。

```java
String originalName = file.getOriginalFilename();               // photo.jpg
String extension = originalName.substring(originalName.lastIndexOf(".")); // .jpg
String newName = UUID.randomUUID().toString() + extension;      // a1b2c3d4-...-e5f6.jpg
```

### 3.3 完整上传逻辑

```java
@PostMapping("/upload")
public Result<String> upload(@RequestParam("file") MultipartFile file) throws IOException {
    if (file.isEmpty()) {
        return Result.error(400, "请选择文件");
    }

    // 生成唯一文件名
    String originalName = file.getOriginalFilename();
    String extension = originalName.substring(originalName.lastIndexOf("."));
    String newName = UUID.randomUUID().toString() + extension;

    // 确保目录存在
    File uploadDir = new File(uploadPath);
    if (!uploadDir.exists()) {
        uploadDir.mkdirs();
    }

    // 保存文件
    File dest = new File(uploadDir, newName);
    file.transferTo(dest);

    return Result.success(newName);  // 返回文件名，前端可以用来拼接访问 URL
}
```

## 四、文件大小限制

在 `application.yml` 中配置：
```yaml
spring:
  servlet:
    multipart:
      max-file-size: 10MB      # 单个文件最大 10MB
      max-request-size: 50MB   # 整个请求最大 50MB（多文件上传时）
```

超过限制会抛 `MaxUploadSizeExceededException`，可以在全局异常处理器中拦截。

## 五、文件下载

文件下载的核心是设置响应头 `Content-Disposition`，告诉浏览器这是一个需要下载的文件：

```java
@GetMapping("/download/{filename}")
public ResponseEntity<Resource> download(@PathVariable String filename) throws IOException {
    File file = new File(uploadPath, filename);
    if (!file.exists()) {
        throw new RuntimeException("文件不存在");
    }

    Resource resource = new UrlResource(file.toURI());

    return ResponseEntity.ok()
            .header(HttpHeaders.CONTENT_DISPOSITION,
                    "attachment; filename=\"" + filename + "\"")
            .body(resource);
}
```

- `attachment` 表示下载，浏览器会弹出保存对话框
- 如果改成 `inline`，浏览器会尝试直接展示（比如图片、PDF）

## 六、文件列表

查看已上传的所有文件：

```java
@GetMapping("/files")
public Result<List<String>> listFiles() {
    File uploadDir = new File(uploadPath);
    String[] fileNames = uploadDir.list();
    if (fileNames == null) {
        return Result.success(List.of());
    }
    return Result.success(List.of(fileNames));
}
```

## 七、云存储 OSS（了解）

本地存储的问题：
- 服务器磁盘空间有限
- 多台服务器时文件不共享
- 没有 CDN 加速，访问慢

企业项目通常用云存储（对象存储）：
- **阿里云 OSS**（Object Storage Service）
- 腾讯云 COS
- AWS S3

流程：
```
前端上传 → 后端接收 → 后端上传到 OSS → 返回 OSS 的 URL 给前端
```

阿里云 OSS 的使用需要引入 SDK，配置 AccessKey，这里了解概念即可，实战项目时再集成。

## 练习

### 练习 1：实现文件上传、列表、下载接口

1. `POST /files/upload` — 上传文件，返回生成的文件名
2. `GET /files` — 查看已上传的文件列表
3. `GET /files/download/{filename}` — 下载指定文件

**答案**：已在 `file-demo` 项目中实现。`FileController` 包含三个接口：上传使用 `MultipartFile` 接收文件并用 UUID 重命名保存；列表接口读取上传目录的文件名列表；下载接口通过 `ResponseEntity<Resource>` 返回文件并设置 `Content-Disposition: attachment` 响应头。

### 练习 2：思考题

1. 为什么要用 UUID 重命名文件？
2. 如果上传的文件超过 10MB，会发生什么？怎么处理？
3. 本地存储和云存储（OSS）各自的优缺点？

**答案**：

1. 防重名覆盖。多个用户都上传 `photo.jpg`，后面的会覆盖前面的。UUID 保证每个文件名全局唯一，永远不会冲突。

2. 会抛出 `MaxUploadSizeExceededException` 异常。应该在全局异常处理器（`@RestControllerAdvice`）中捕获这个异常，返回友好的错误提示，如 `Result.error(400, "文件大小超过限制，最大 10MB")`。

3. **本地存储**：优点是简单免费、不依赖外部服务；缺点是磁盘空间有限、多台服务器文件不共享、没有 CDN 加速。**云存储（OSS）**：优点是自动扩容、CDN 全球加速、多节点共享、高可用；缺点是需要付费、依赖外部服务、需要配置 AccessKey。
