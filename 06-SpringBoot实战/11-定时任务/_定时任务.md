# 定时任务

## 一、什么是定时任务

有些功能不需要用户触发，而是按固定时间自动执行：

- 每天凌晨 2 点清理过期订单
- 每 5 分钟同步第三方数据
- 每周一早上 9 点发送周报邮件
- 每 30 秒检查一次服务器健康状态

Spring Boot 内置了定时任务支持，用两个注解就能实现：`@EnableScheduling` + `@Scheduled`。

## 二、快速入门

### 2.1 开启定时任务

在启动类上加 `@EnableScheduling`：

```java
@SpringBootApplication
@EnableScheduling  // 开启定时任务支持
public class ScheduleDemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(ScheduleDemoApplication.class, args);
    }
}
```

### 2.2 编写定时任务

```java
import org.springframework.scheduling.annotation.Scheduled;
import org.springframework.stereotype.Component;
import java.time.LocalDateTime;

@Component  // 必须被 Spring 管理
public class MyTask {

    @Scheduled(fixedRate = 5000)  // 每 5 秒执行一次
    public void printTime() {
        System.out.println("当前时间：" + LocalDateTime.now());
    }
}
```

启动项目后，控制台每 5 秒输出一次当前时间，不需要任何请求触发。

## 三、@Scheduled 三种调度方式

### 3.1 fixedRate — 固定频率

```java
@Scheduled(fixedRate = 5000)  // 每 5 秒执行一次
public void task1() {
    System.out.println("fixedRate 执行：" + LocalDateTime.now());
}
```

**特点**：从上一次**开始**执行的时间点算起，间隔 5 秒后再执行。即使上一次还没执行完，到时间了也会触发下一次（排队等待）。

```
|--任务1(3秒)--|  |--任务2--|  |--任务3--|
0s            3s  5s        8s 10s
```

### 3.2 fixedDelay — 固定延迟

```java
@Scheduled(fixedDelay = 5000)  // 上一次执行完后，等 5 秒再执行
public void task2() {
    System.out.println("fixedDelay 执行：" + LocalDateTime.now());
}
```

**特点**：从上一次**结束**的时间点算起，间隔 5 秒后再执行。

```
|--任务1(3秒)--|     |--任务2(3秒)--|     |--任务3--|
0s            3s    8s           11s    16s
                ↑等5秒              ↑等5秒
```

### 3.3 cron — Cron 表达式

```java
@Scheduled(cron = "0 0 2 * * ?")  // 每天凌晨 2 点执行
public void task3() {
    System.out.println("cron 执行：" + LocalDateTime.now());
}
```

**特点**：最灵活，能表达几乎所有时间规则。

### 3.4 三种方式对比

| 方式 | 适用场景 | 例子 |
|------|---------|------|
| `fixedRate` | 固定频率执行，不关心上一次是否完成 | 每 5 秒采集一次监控数据 |
| `fixedDelay` | 等上一次完成后再执行，避免任务堆积 | 每次同步完数据后等 10 秒再同步 |
| `cron` | 按特定时间点执行 | 每天凌晨 2 点清理数据 |

## 四、Cron 表达式详解

### 4.1 格式

Spring 的 Cron 表达式有 6 个字段：

```
秒  分  时  日  月  周
```

| 位置 | 字段 | 取值范围 | 特殊字符 |
|------|------|---------|----------|
| 1 | 秒 | 0-59 | , - * / |
| 2 | 分 | 0-59 | , - * / |
| 3 | 时 | 0-23 | , - * / |
| 4 | 日 | 1-31 | , - * / ? |
| 5 | 月 | 1-12 | , - * / |
| 6 | 周 | 0-7 (0和7都是周日) | , - * / ? |

### 4.2 特殊字符含义

| 字符 | 含义 | 例子 |
|------|------|------|
| `*` | 任意值 | `* * * * * ?` 每秒执行 |
| `?` | 不指定（日和周互斥时用） | 日和周不能同时指定具体值 |
| `,` | 枚举 | `0 0 2,14 * * ?` 每天 2 点和 14 点 |
| `-` | 范围 | `0 0 9-17 * * ?` 每天 9 点到 17 点，每小时执行 |
| `/` | 步长 | `0 0/5 * * * ?` 每 5 分钟执行 |

### 4.3 常用 Cron 表达式

| 表达式 | 含义 |
|--------|------|
| `0/5 * * * * ?` | 每 5 秒 |
| `0 0/1 * * * ?` | 每 1 分钟 |
| `0 0 * * * ?` | 每小时整点 |
| `0 0 2 * * ?` | 每天凌晨 2 点 |
| `0 0 9 * * MON-FRI` | 工作日每天早上 9 点 |
| `0 0 0 1 * ?` | 每月 1 号零点 |
| `0 0 0 ? * MON` | 每周一零点 |
| `0 0 2 1 * ?` | 每月 1 号凌晨 2 点 |

### 4.4 日和周的互斥

日和周不能同时指定具体值，其中一个必须用 `?`：

```
0 0 2 15 * ?    ← 正确：每月 15 号凌晨 2 点（周用 ?）
0 0 2 ? * MON   ← 正确：每周一凌晨 2 点（日用 ?）
0 0 2 15 * MON  ← 错误：日和周不能同时指定
```

## 五、实际应用场景

### 5.1 定时清理过期数据

```java
@Scheduled(cron = "0 0 3 * * ?")  // 每天凌晨 3 点
public void cleanExpiredOrders() {
    // 删除 30 天前的已取消订单
    log.info("开始清理过期订单...");
    int count = orderService.deleteExpiredOrders(30);
    log.info("清理完成，共删除 {} 条", count);
}
```

### 5.2 定时同步数据

```java
@Scheduled(fixedDelay = 60000)  // 上次完成后等 1 分钟
public void syncProductStock() {
    log.info("开始同步库存...");
    // 从第三方 API 拉取最新库存
    stockService.syncFromThirdParty();
    log.info("库存同步完成");
}
```

### 5.3 定时发送统计报告

```java
@Scheduled(cron = "0 0 9 ? * MON")  // 每周一早上 9 点
public void sendWeeklyReport() {
    log.info("生成周报...");
    Report report = reportService.generateWeeklyReport();
    emailService.send("admin@example.com", report);
    log.info("周报已发送");
}
```

## 六、注意事项

### 6.1 默认单线程

Spring 的定时任务默认只有**一个线程**。如果有多个定时任务，它们会排队执行：

```java
@Scheduled(fixedRate = 1000)  // 每 1 秒
public void taskA() {
    Thread.sleep(5000);  // 模拟耗时 5 秒
}

@Scheduled(fixedRate = 1000)  // 每 1 秒
public void taskB() {
    // taskA 占着线程时，taskB 只能等
}
```

taskA 占着线程 5 秒，taskB 只能等 taskA 完成才能执行。

### 6.2 配置线程池

在 `application.yml` 中配置定时任务线程池大小：

```yaml
spring:
  task:
    scheduling:
      pool:
        size: 5  # 5 个线程并发执行定时任务
```

或者用 Java 配置：

```java
import org.springframework.context.annotation.Configuration;
import org.springframework.scheduling.annotation.SchedulingConfigurer;
import org.springframework.scheduling.concurrent.ThreadPoolTaskScheduler;
import org.springframework.scheduling.config.ScheduledTaskRegistrar;

@Configuration
public class ScheduleConfig implements SchedulingConfigurer {

    @Override
    public void configureTasks(ScheduledTaskRegistrar registrar) {
        ThreadPoolTaskScheduler scheduler = new ThreadPoolTaskScheduler();
        scheduler.setPoolSize(5);
        scheduler.setThreadNamePrefix("scheduled-");
        scheduler.initialize();
        registrar.setTaskScheduler(scheduler);
    }
}
```

### 6.3 异常处理

定时任务中抛异常不会导致应用崩溃，但该次执行会终止。建议加 try-catch：

```java
@Scheduled(fixedRate = 5000)
public void safeTask() {
    try {
        // 业务逻辑
    } catch (Exception e) {
        log.error("定时任务执行失败", e);
    }
}
```

### 练习 3：思考题

1. `fixedRate` 和 `fixedDelay` 的区别是什么？
2. 为什么定时任务默认单线程可能导致问题？怎么解决？
3. 写出以下场景的 Cron 表达式：
   - 每天中午 12 点
   - 工作日（周一到周五）每天早上 8 点
   - 每月最后一天晚上 11 点

**答案**：

1. `fixedRate` 从上一次**开始**时间算起，间隔固定时间后触发下一次（即使上一次还没执行完也会排队）。`fixedDelay` 从上一次**结束**时间算起，等上一次执行完后再间隔固定时间触发下一次。如果任务耗时长，`fixedRate` 可能堆积，`fixedDelay` 不会。

2. 默认只有一个线程执行所有定时任务。如果 taskA 耗时 5 秒，那 taskB 必须等 taskA 完成才能执行，导致 taskB 被延迟。解决方案：在 `application.yml` 中配置 `spring.task.scheduling.pool.size` 增大线程池，或实现 `SchedulingConfigurer` 自定义线程池。

3. Cron 表达式：
   - 每天中午 12 点：`0 0 12 * * ?`
   - 工作日每天早上 8 点：`0 0 8 * * MON-FRI`
   - 每月最后一天晚上 11 点：`0 0 23 L * ?`（`L` 表示最后一天）
