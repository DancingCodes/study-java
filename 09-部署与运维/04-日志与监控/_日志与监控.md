# 日志与监控

## 一、为什么需要日志和监控

应用上线后，不能靠「用户反馈」来发现问题：

| 没有日志/监控 | 有日志/监控 |
|--------------|------------|
| 出问题了不知道原因 | 日志记录了完整的错误信息 |
| 不知道服务是否正常 | 监控实时展示服务状态 |
| 流量暴增了才知道 | 监控提前预警 |
| 排查问题靠猜 | 日志 + 链路追踪精准定位 |

## 二、日志收集 — ELK

### 2.1 ELK 是什么

| 组件 | 全称 | 职责 |
|------|------|------|
| **E** | Elasticsearch | 存储和搜索日志 |
| **L** | Logstash | 收集、处理、转发日志 |
| **K** | Kibana | 日志可视化（Web 界面） |

工作流程：
```
应用日志 → Logstash（收集/过滤） → Elasticsearch（存储/搜索） → Kibana（展示）
```

在小型场景中，也可以用 **Filebeat** 替代 Logstash（更轻量）：
```
应用日志文件 → Filebeat（采集） → Elasticsearch → Kibana
```

### 2.2 Docker 部署 ELK

```yaml
version: '3.8'

services:
  elasticsearch:
    image: elasticsearch:8.11.0
    container_name: es
    environment:
      - discovery.type=single-node
      - xpack.security.enabled=false
      - "ES_JAVA_OPTS=-Xms512m -Xmx512m"
    ports:
      - "9200:9200"
    volumes:
      - es-data:/usr/share/elasticsearch/data
    networks:
      - elk-net

  kibana:
    image: kibana:8.11.0
    container_name: kibana
    ports:
      - "5601:5601"
    environment:
      - ELASTICSEARCH_HOSTS=http://es:9200
    depends_on:
      - elasticsearch
    networks:
      - elk-net

  filebeat:
    image: elastic/filebeat:8.11.0
    container_name: filebeat
    volumes:
      - ./filebeat.yml:/usr/share/filebeat/filebeat.yml:ro
      - /var/log/app:/var/log/app:ro  # 挂载应用日志目录
    depends_on:
      - elasticsearch
    networks:
      - elk-net

volumes:
  es-data:

networks:
  elk-net:
```

### 2.3 Filebeat 配置

```yaml
filebeat.inputs:
  - type: log
    enabled: true
    paths:
      - /var/log/app/*.log
    multiline.pattern: '^\d{4}-\d{2}-\d{2}'  # 按日期行合并多行日志
    multiline.negate: true
    multiline.match: after

output.elasticsearch:
  hosts: ["es:9200"]
  index: "app-logs-%{+yyyy.MM.dd}"
```

### 2.4 在 Kibana 中查看日志

1. 访问 http://localhost:5601
2. Management → Data Views → 创建索引模式 `app-logs-*`
3. Discover 页面搜索和过滤日志
4. 可以按时间、关键词、日志级别筛选

## 三、应用监控 — Prometheus + Grafana

### 3.1 组件说明

| 组件 | 职责 |
|------|------|
| **Prometheus** | 指标采集和存储（时序数据库） |
| **Grafana** | 指标可视化（Dashboard） |
| **Actuator** | Spring Boot 暴露应用指标 |
| **Micrometer** | 指标桥接（Spring Boot → Prometheus 格式） |

工作流程：
```
Spring Boot（Actuator + Micrometer）
    ↓ 暴露 /actuator/prometheus 端点
Prometheus（定时拉取指标数据）
    ↓
Grafana（可视化展示）
```

### 3.2 Spring Boot 配置

引入依赖：

```xml
<!-- Actuator -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>

<!-- Prometheus 指标格式 -->
<dependency>
    <groupId>io.micrometer</groupId>
    <artifactId>micrometer-registry-prometheus</artifactId>
</dependency>
```

配置：

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health,info,prometheus  # 暴露的端点
  metrics:
    tags:
      application: myapp                 # 应用标签
```

启动后访问 http://localhost:8080/actuator/prometheus 可以看到指标数据。

### 3.3 Docker 部署 Prometheus + Grafana

```yaml
version: '3.8'

services:
  prometheus:
    image: prom/prometheus:latest
    container_name: prometheus
    ports:
      - "9090:9090"
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml
    networks:
      - monitor-net

  grafana:
    image: grafana/grafana:latest
    container_name: grafana
    ports:
      - "3000:3000"
    environment:
      - GF_SECURITY_ADMIN_PASSWORD=admin123
    depends_on:
      - prometheus
    networks:
      - monitor-net

networks:
  monitor-net:
```

### 3.4 Prometheus 配置

```yaml
global:
  scrape_interval: 15s  # 每 15 秒采集一次

scrape_configs:
  - job_name: 'spring-boot-app'
    metrics_path: '/actuator/prometheus'
    static_configs:
      - targets: ['host.docker.internal:8080']  # 应用地址
        labels:
          application: myapp
```

### 3.5 Grafana 配置

1. 访问 http://localhost:3000（账号 admin，密码 admin123）
2. Configuration → Data Sources → Add Prometheus（URL: http://prometheus:9090）
3. Dashboards → Import → 输入模板 ID **12900**（Spring Boot Dashboard）
4. 即可看到 JVM 内存、线程、HTTP 请求量、响应时间等指标

### 3.6 常用监控指标

| 指标 | 说明 |
|------|------|
| JVM 内存使用 | 堆内存、非堆内存 |
| JVM 线程数 | 活跃线程、峰值线程 |
| GC 情况 | GC 次数、GC 耗时 |
| HTTP 请求量 | QPS、请求总数 |
| HTTP 响应时间 | P50、P95、P99 |
| 数据库连接池 | 活跃连接数、等待数 |
| 自定义业务指标 | 订单量、支付成功率等 |

## 四、告警（了解）

Grafana 支持配置告警规则：
- CPU 使用率 > 80% → 发邮件/钉钉通知
- 接口响应时间 P99 > 2s → 告警
- 错误率 > 5% → 告警

告警渠道：邮件、钉钉、企业微信、Slack 等。

## 五、总结

```
日志收集：ELK（Elasticsearch + Logstash/Filebeat + Kibana）
          → 出了问题，看日志排查

应用监控：Prometheus + Grafana
          → 实时掌握应用健康状态

告警通知：Grafana Alerting
          → 问题发生时及时通知
```
